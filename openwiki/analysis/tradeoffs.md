# Tradeoff definition and discretization

`DataProcessor.define_tradeoffs()` is the stateless transformation boundary used by `ArchSpaceCore` and `PatternAnalysis`. It optionally applies `SemanticNaNHandler.impute_outcomes`, selects a method, and returns `(labeled_df, schemes, tradeoff_indices, pareto_front)`. `get_tradeoff_indices()` groups every categorical combination into a comma-separated key; `get_tradeoffs()` turns those groups into counts.

Supported methods are `discretization`, `clustering`, `threshold`, `pareto`/`pareto_nadir`, `pareto_epsilon`, and `pareto_knee`. Equal-width discretization uses `get_bins()` with a small range buffer and labels supplied per objective or generated as `level_1`...; label count must equal `n_bins`. Clustering runs K-Means per objective and selects `k` using silhouette score, then cuts at centroid midpoints. Thresholds use objective direction (`maximize`) to interpret `<=`, `<`, `>=`, or `>` and create `QualityBin` metadata.

Objective direction affects every Pareto method: each `QualityObjective` becomes `"max"` or `"min"` in the `paretoset` sense list; Nadir reverses labels for maximize columns, epsilon/knee normalize raw values without reversing the DataFrame and use direction-aware Pareto/utopia decisions. Method-by-method NaN behavior is: ordinary discretization passes NaNs to `pd.cut` (they remain unlabeled) unless objectives triggered imputation; K-Means drops NaNs for fitting and leaves corresponding output labels missing; threshold `pd.cut` leaves NaNs missing; Pareto methods require finite objective values for reliable `paretoset`/scaling and can fail or exclude rows. Semantic NaNs are imputed only when `objectives` are supplied; default worst-case imputation places missing values outside the good region, `fixed_value` uses its explicit value, and `drop` is not implemented by the handler (rows remain). Without objectives, NaNs pass into the selected algorithm and may be excluded by `pd.cut` or fail Pareto/scaling.

Pareto Nadir marks points relative to the worst boundary of the Pareto front. Epsilon mode computes a Pareto mask using `paretoset`, normalizes objectives, measures nearest-front distance, and labels epsilon-optimal versus out regions. Knee mode finds the Pareto point nearest the direction-aware utopia point and labels points within tolerance. Pareto methods require the `paretoset` package and matching objective columns; no matching objectives raises `ValueError`, while an empty compliant set produces schemes with no bins in the epsilon/knee implementations. Constant columns and NaNs can make scaling or `pd.cut` degenerate, so callers should impute/drop them first according to objective metadata.

Threshold semantics are direction-aware: for maximize, no operator means `>=` and labels are reversed so the second label is satisfactory; for minimize, no operator means `<=`; explicit `<`/`>` change boundary inclusion via `pd.cut`. Invalid operators raise `ValueError`. Discretization uses observed/range-derived edges and can fail on empty or nonnumeric columns; a labels dictionary with the wrong length raises `ValueError`. K-Means skips empty columns and may fall back to one cluster for tiny data. The public method raises `NotImplementedError` for unknown methods.

The output invariant is that each scheme describes the labels in its corresponding categorical outcome column; downstream tradeoff matching depends on objective names and labels remaining aligned. `PatternAnalysis._update_tradeoff_membership()` updates configured `Tradeoff.has_points` and `point_count` after definition. Tradeoff membership is resolved by matching `Tradeoff.elements` against the categorical `discrete_df` and uses the precomputed `tradeoff_indices` map. The grouped index values are NumPy arrays produced by pandas `groupby(...).indices`: they identify the DataFrame's index labels, not a guaranteed zero-based positional sequence. There is no separate original-label-to-position conversion in `DataProcessor`; the current session integration contract is aligned zero-based frames or an explicit normalization before subset operations. Session subset code treats values as positional in several `iloc` paths, so a non-default/reordered index can select wrong rows or fail. Threshold and epsilon methods have explicit parameter validation in the session façade (`thresholds` and `epsilon` are mandatory).

Coverage gaps to check before extending this component include empty/constant columns, malformed label counts, objective-less NaN input, non-default indices, empty Pareto fronts, duplicate configuration/tradeoff combinations, and K-Means tiny samples. Existing `tests/test_data_processor.py` covers representative happy paths, threshold direction, explicit ranges, and epsilon behavior but does not prove these integration boundaries or every method's NaN behavior. `tests/test_tradeoff_entity.py` covers model membership behavior. Change the implementation and scheme metadata together; plots and robustness REGRET derive their boundaries from `DiscretizationScheme.bins`.
