# Project Summary: Analysis Toolkit for Architectural Patterns

This project provides a framework for analyzing performance and other quality attributes of various architectural patterns, including related design decisions and tradeoffs. The range of techniques include sensitivity analysis, PRIM and CART, among other. These techniques are data-driven, meaning the system is designed to consume datasets (e.g., CSV files) generated by external simulation tools like `AP4FED`, which specializes in architectural patterns for Federated Learning and microservices.

The framework is designed to be extensible to different domains. Currently, it is tailored for analyzing data from:

*   **Microservices Architectures:** Using simulation data for patterns like Gateway Offloading, CQRS, and Anti-Corruption Layer.
*   **Federated Learning (FL) Systems:** Using simulation data for patterns like Client Registry, Client Selector, Client Cluster, and others.

## Core Components (new system):

*   **`archspaces/`**: Contains Python classes that define the core modeling and analysis capabilities.
    *   `ArchSpace` (base class): Provides generic functionalities for **data loading** (from CSVs or other formats), outcome discretization, robustness calculation, scenario discovery (PRIM and CART), and visualization.
    *   Specialized subclasses for different domains (e.g., microservices, federated learning) that understand the specific parameters and quality attributes from the input data.
*   **`patterns/`**: Contains directories for each architectural pattern. Each directory holds:
    *   **Analysis Scripts:** Python scripts (replacing former Jupyter notebooks) that use the `archspaces` framework to load simulation data and generate analyses and visualizations.
    *   **Data Files (e.g., `.csv`):** Simulation results generated externally (e.g., by `AP4FED`) that are used as input for the analysis scripts.

## Main Features:

*   **Architectural Pattern Analysis Library:** A collection of Python classes to model and analyze data from various common architectural patterns.
*   **Domain Specialization:** Supports analysis of data from Microservices and Federated Learning systems.
*   **Quantitative, Data-Driven Analysis:** Tools to quantify the impact of architectural decisions on quality attributes based on pre-existing simulation data.
*   **Trade-off Analysis:** Tools to understand the trade-offs when applying and combining different architectural patterns by analyzing the provided datasets.
*   **Sensitivity Analysis:** Methods to evaluate the sensitivity of a system's performance to changes in design parameters found in the input data.
*   **Extensibility:** The framework is designed to be extended with new analysis techniques and to support data from new architectural patterns and domains.

## Workflow:

1.  **Data Generation (External):** Simulations are run using an external tool (like `AP4FED`) to generate performance and behavior data for specific architectural patterns. This data is typically saved in CSV files.
2.  **Data Loading & Analysis:** An analysis script in the `patterns/` directory loads the generated data using the appropriate `ArchSpace` class.
3.  **Analysis Execution:** The script leverages the `ArchSpace` methods to perform various analyses like sensitivity analysis, trade-off visualization, and scenario discovery.
4.  **Result Generation:** The script outputs visualizations, reports, and other artifacts that provide insights into the architectural decisions and their consequences.
